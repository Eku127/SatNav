# Seq2Seq 模型训练问题的根本原因分析

## 核心问题

**模型发现只要预测 MOVE_FORWARD 就可以获得低 loss**

## 根本原因

### 1. 数据不平衡（主要原因）

**训练数据中的动作分布**：
- `MOVE_FORWARD`: **89.6%** （占主导地位）
- `TURN_LEFT`: 1.5%
- `TURN_RIGHT`: 9.0%
- `STOP`: 0%

**问题**：
- 如果模型总是预测 `MOVE_FORWARD`，在 89.6% 的情况下都是对的
- Cross-entropy loss 会很低（因为大部分预测都正确）
- 模型不需要学习导航，只需要学习"总是预测最常见的动作"

### 2. 数据缺乏多样性（次要但关键）

**训练数据特点**：
- 只有 11 个相同的训练 episode
- 只有 1 个相同的验证 episode
- 所有 episode 使用相同的轨迹和指令

**问题**：
- 模型无法学习"不同观察 → 不同动作"的映射
- 模型只能学习到数据中的统计模式（MOVE_FORWARD 占主导）
- 即使有 RGB 和 Instruction，模型也不需要使用它们

### 3. 模型的学习策略

**模型学到的**：
```
策略1: 总是预测 MOVE_FORWARD
  - 正确率: 89.6%
  - Loss: 低（因为大部分预测正确）
  - 不需要理解任何输入

策略2: 学习导航（RGB + Instruction → Action）
  - 需要理解视觉和语言
  - 需要学习复杂的映射
  - Loss: 可能更高（因为学习困难）
```

**结果**：模型选择了策略1（简单、低 loss）

### 4. 为什么 Class Weights 没有完全解决问题

**Class Weights 的作用**：
- 增加 TURN_LEFT/TURN_RIGHT 的权重（20.0x）
- 降低 MOVE_FORWARD 的权重（0.05x）

**为什么还不够**：
1. **数据量太少**：
   - TURN_LEFT 只有 1.5%，即使权重 20x，样本数仍然很少
   - 模型可能过拟合到少数几个 TURN_LEFT 样本

2. **数据重复**：
   - 所有 episode 相同，模型看到的是同样的几个 TURN_LEFT 位置
   - 模型可能学到"在这几个特定位置转左"，而不是"根据观察转左"

3. **模型容量**：
   - 模型可能足够简单，可以记住所有训练样本
   - 不需要学习泛化能力

## 实验证据

### 证据1: Ablation Study
- 移除 RGB: 影响 0.1986（高）
- 移除 Instruction: 影响 0.0092（低）
- **但移除后预测不变** → 模型不使用这些特征做决策

### 证据2: Prev_Action Pattern Test
- 不同历史 → 相同预测
- 不同观察 → 相同预测
- **模型忽略所有输入** → 只使用统计先验

### 证据3: 训练 vs 评估
- 训练 loss: 低（0.11）
- 评估表现: 差（只走直线）
- **模型学到了模式匹配，不是导航**

## 解决方案优先级

### 🔴 优先级1: 生成多样化数据（必须）

**为什么最重要**：
- 没有多样化的数据，模型无法学习导航
- 即使有完美的模型架构和训练策略，也无法解决数据问题

**需要什么**：
1. **多样化的轨迹**：
   - 不同的起点和终点
   - 不同的路径（直线、转弯、复杂路径）
   - 不同的场景

2. **平衡的动作分布**：
   - MOVE_FORWARD: ~50-60%
   - TURN_LEFT: ~15-20%
   - TURN_RIGHT: ~15-20%
   - STOP: ~5-10%

3. **多样化的指令**：
   - 不同的语言描述
   - 不同的路径描述方式

### 🟡 优先级2: 调整训练策略

**在有了多样化数据后**：
1. **Class Weights**：
   - 平衡动作分布
   - 但需要配合多样化数据

2. **Scheduled Sampling**：
   - 减少 exposure bias
   - 让模型看到自己的错误

3. **Inflection Weighting**：
   - 强调关键决策点
   - 帮助模型学习何时转弯

### 🟢 优先级3: 模型架构调整

**可选优化**：
1. **尝试 `use_prev_action=False`**：
   - 强制模型使用 RGB+Instruction
   - 但需要多样化数据支持

2. **增加模型容量**：
   - 如果数据足够，可以增加模型复杂度
   - 但当前数据太少，可能过拟合

## 总结

### 核心结论

**模型发现只要预测 MOVE_FORWARD 就可以获得低 loss，根本原因是数据集中 MOVE_FORWARD 占据了太多比例（89.6%）。**

### 问题链条

```
数据不平衡 (89.6% MOVE_FORWARD)
    ↓
模型学到"总是预测 MOVE_FORWARD"
    ↓
训练 loss 低（因为大部分预测正确）
    ↓
但模型没有学到导航能力
    ↓
评估时表现差（只会走直线）
```

### 解决路径

```
生成多样化数据（必须）
    ↓
平衡动作分布（MOVE_FORWARD ~50-60%）
    ↓
模型可以学习导航（RGB + Instruction → Action）
    ↓
训练 loss 和评估表现都会改善
```

## 下一步行动

1. **立即行动**：生成更多样化的训练数据
   - 不同轨迹
   - 平衡的动作分布
   - 多样化的指令

2. **验证**：有了新数据后，重新运行特征重要性实验
   - 应该看到模型开始使用 RGB 和 Instruction
   - 不同观察应该产生不同预测

3. **优化**：在多样化数据基础上，调整训练策略
   - Class weights
   - Scheduled sampling
   - 其他正则化技术
