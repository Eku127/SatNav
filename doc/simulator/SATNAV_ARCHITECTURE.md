# SatNav Architecture Overview

This document explains the current SatNav structure for readers and agents that
need to understand how the system works before editing it. It focuses on the
simulator, task, dataset, and training/evaluation flow. It intentionally avoids
large code snippets.

## What SatNav Is

SatNav is a continuous-state Vision-and-Language Navigation platform built on
satellite maps. Unlike indoor VLN systems that move through a graph of discrete
viewpoints, SatNav represents the agent as a moving point in geographic space.

The agent state is:

- position: `[longitude, latitude, altitude]`
- heading: degrees, where `0` means north

The environment uses local GeoTIFF satellite maps as scenes. RGB observations
are generated by cropping and rotating the satellite map around the agent's
current geographic position.

## High-Level Flow

The runtime stack is intentionally small:

```text
run.py / scripts
    |
    v
Trainer or Evaluator
    |
    v
Env
    |
    +-- SatNavDataset -> VLNEpisode objects
    |
    +-- VLNTask
            |
            +-- Sensors: RGB, instruction, agent pose
            +-- Measures: distance, success, SPL, path length, top-down map
            |
            v
        Simulator interface
            |
            v
        SatSimWrapper
            |
            v
        SatSim + SatelliteCamera + GeoUtils
```

`Env` is the integration point. It owns the dataset iterator, the active
episode, the task, the simulator, step counting, and episode termination.

## Main Directories

### `satnav/core/`

Core interfaces and data structures.

- `env.py`: connects dataset, task, and simulator.
- `episode.py`: defines `VLNEpisode`, `NavigationGoal`, and `InstructionData`.
- `simulator.py`: defines the abstract simulator interface and `AgentState`.
- `utils.py`: geographic distance and pose utility functions.

### `satnav/dataset/`

Dataset loading.

- `satnav_dataset.py`: loads JSON or JSON.GZ episode files into `VLNEpisode`
  objects.
- `offline_trajectory_dataset.py`: reads pre-rendered trajectory data for
  offline imitation learning.

### `satnav/sims/`

Simulator factory and SatSim implementation.

- `__init__.py`: creates the configured simulator. The supported simulator type
  is currently `satsim`.
- `satsim_wrapper.py`: adapts SatSim to the shared `Simulator` interface.
- `satsim/satsim.py`: loads GeoTIFF scenes, stores agent state, applies actions,
  and returns RGB observations.
- `satsim/camera.py`: computes camera footprint, crops map imagery, rotates it,
  and resizes it.
- `satsim/geoutils.py`: converts between WGS84 and Web Mercator coordinates.

### `satnav/task/`

VLN task logic.

- `vln_task.py`: resets episodes, applies actions, updates measures, and builds
  observations.
- `sensors.py`: implements RGB, instruction, and relative agent-pose sensors.
- `measures.py`: implements navigation metrics.
- `actions.py`: defines `STOP`, `MOVE_FORWARD`, `TURN_LEFT`, and `TURN_RIGHT`.

### `satnav/models/` and `satnav/training/`

Learning and evaluation.

- `models/baselines/`: Seq2Seq, CMA, random, and greedy policies.
- `training/offline_trainer.py`: offline imitation training and online rollout
  evaluation entry point.
- `training/evaluator.py`: evaluates checkpoints in the simulator.

## Episode Data Model

An episode describes one navigation task:

- `episode_id`: unique episode id
- `scene_id`: GeoTIFF scene name or path
- `start_position`: `[longitude, latitude, altitude]`
- `start_rotation`: initial heading in degrees
- `goals`: one or more goal positions
- `reference_path`: continuous ground-truth path as geographic coordinates
- `instruction`: natural-language navigation instruction
- `trajectory_type`: optional task category, such as `Boundary`,
  `LandmarkSet`, or `Road`

The dataset loader supports plain JSON and gzipped JSON. If `SCENES_DIR` is
configured, scene ids are resolved relative to that directory.

## Reset and Step Lifecycle

### Reset

When `Env.reset()` is called:

1. The next episode is pulled from `SatNavDataset`.
2. `VLNTask.reset()` receives that episode.
3. The simulator loads the episode scene.
4. The simulator agent state is set to the episode start position and heading.
5. Sensors and measures reset their episode-specific state.
6. Initial observations are returned.

### Step

When `Env.step(action)` is called:

1. `VLNTask` validates and normalizes the action.
2. `SatSim` applies the action in Web Mercator coordinates.
3. Navigation measures update from the new simulator state.
4. Sensors produce the next observation dictionary.
5. `Env` marks the episode done if `STOP` was called or the max step count was
   reached.

The success metric does not terminate the episode by itself. This matches the
VLN-style convention where the agent must explicitly call `STOP`.

## Coordinate Systems

SatNav exposes positions as WGS84 geographic coordinates:

```text
[longitude, latitude, altitude]
```

SatSim internally converts these positions to EPSG:3857 Web Mercator. This
keeps movement and camera footprint calculations simple because local movement
can be treated as meter-scale planar motion.

The boundary between the two systems is the simulator API:

- external API: WGS84 coordinates
- internal movement/rendering: EPSG:3857 meters

GeoTIFF scenes are opened with Rasterio. If a scene is not already EPSG:3857,
SatSim opens it through a `WarpedVRT` reprojected to EPSG:3857.

## Actions

SatNav uses four discrete navigation actions:

| Action | Effect |
| --- | --- |
| `STOP` | End the episode when used through `Env.step()` |
| `MOVE_FORWARD` | Move forward by `SIMULATOR.FORWARD_STEP_SIZE` meters |
| `TURN_LEFT` | Decrease heading by `SIMULATOR.TURN_ANGLE` degrees |
| `TURN_RIGHT` | Increase heading by `SIMULATOR.TURN_ANGLE` degrees |

Forward movement is computed in Mercator space from the current heading. If the
new position would make the camera view leave the map bounds, the agent stays in
place.

## Rendering Model

`SatelliteCamera` renders each RGB observation from the current GeoTIFF scene:

1. Use altitude and horizontal field of view to compute the visible ground
   footprint.
2. Convert the footprint to Web Mercator bounds.
3. Check that the rotated view stays inside the scene bounds.
4. Crop the required raster window.
5. Rotate the crop according to the agent heading.
6. Resize the image to the configured RGB sensor size.

The camera also provides a safety margin used by `SatSim.is_navigable()`. The
margin keeps the entire rotated camera footprint inside the map, not just the
agent center point.

## Observations

The default task always provides three observations:

- `rgb`: satellite image crop from the simulator
- `instruction`: instruction text from the current episode
- `agent_pose`: relative ego-frame pose from episode start

`agent_pose` is represented as:

```text
[delta_forward_m, delta_right_m, sin(delta_heading), cos(delta_heading)]
```

The forward axis is the agent's initial heading at episode start. This makes the
pose feature independent of absolute north/east orientation.

## Metrics

Common metrics are implemented in `satnav/task/measures.py`:

- `DISTANCE_TO_GOAL`: geodesic distance from current position to goal
- `SUCCESS`: whether the agent called `STOP` within the configured threshold
- `ORACLE_SUCCESS`: whether the agent ever entered the success radius
- `PATH_LENGTH`: total traveled distance
- `SPL`: success weighted by path length
- `TOP_DOWN_MAP`: optional debug visualization

`SUCCESS_DISTANCE` can be a scalar or a per-trajectory-type mapping. The task
updates the threshold on reset when an episode has a known `trajectory_type`.

## Training and Evaluation

The current main learning path uses offline imitation learning:

1. Trajectory generation produces pre-rendered RGB frames and action labels.
2. `OfflineTrajectoryDataset` reads those files.
3. `offline_trainer` trains Seq2Seq or CMA policies without running the
   simulator during each training batch.
4. Evaluation loads a checkpoint and returns to `Env` + `SatSim` for online
   rollout.

This separation keeps training fast while preserving simulator-based evaluation.

The main quickstart script is:

```text
scripts/quickstart_models.sh
```

Model-specific scripts live under:

- `scripts/seq2seq/`
- `scripts/cma/`

## Configuration Entry Points

The main task configuration is:

```text
configs/satnav_task.yaml
```

Baseline training and evaluation configs are under:

```text
configs/baselines/
```

Important fields:

- `ENVIRONMENT.MAX_EPISODE_STEPS`
- `SIMULATOR.TYPE`
- `SIMULATOR.FORWARD_STEP_SIZE`
- `SIMULATOR.TURN_ANGLE`
- `SIMULATOR.RGB_SENSOR`
- `TASK.SUCCESS_DISTANCE`
- `TASK.MEASUREMENTS`
- `DATASET.DATA_PATH`
- `DATASET.SCENES_DIR`

## How to Add or Modify Components

When editing the simulator stack, prefer these boundaries:

- New map rendering behavior belongs in `satnav/sims/satsim/camera.py`.
- Movement, scene loading, and navigability belong in
  `satnav/sims/satsim/satsim.py`.
- Public simulator interface compatibility belongs in
  `satnav/sims/satsim_wrapper.py`.
- New observations belong in `satnav/task/sensors.py`.
- New metrics belong in `satnav/task/measures.py`.
- Episode schema changes belong in `satnav/core/episode.py` and
  `satnav/dataset/satnav_dataset.py`.
- Training-only data changes belong in `satnav/dataset/offline_trajectory_dataset.py`.

Avoid hard-coding dataset or map paths in code. Prefer config fields and
scripts.
